## 4. TRACE: 답하기 전에 근거를 확인하는 점검 루프 — 70초

### 핵심 메시지

VLM의 응답을 바로 최종 답으로 쓰지 않고, 근거 확인을 거쳐 확정·재관측·인계 중 하나를 선택한다.

### 화면 본문

**질의 → 관측 → VLM 판독 → 근거 확인 → 확정 / 재관측 / 인계**

- 판독: Qwen3-VL이 사람 유무·자세·관측 제한을 구조화해 출력
- 근거 확인: 어떤 프레임을 근거로 썼는지 기록하고, 채택 규칙을 통과한 관측만 답에 사용
- 검출 게이트(선택): 같은 프레임에서 YOLO가 사람 후보를 정확히 1명 찾을 때만 통과

### 자료

- `s04_loop/trace_loop_diagram.png` — 제목과 검출 게이트 포함.
- `s04_loop/trace_loop_diagram_simple.png` — 게이트를 뺀 단순판. 10장 결론에 재사용.

PPT에서 다시 그릴 경우 이 그림을 배치 참고로 쓴다.

### 발표 메모

"VLM이 답을 내면, 그 답이 어떤 화면에 근거했는지와 그 화면이 채택 조건을 통과하는지를 먼저 확인합니다. 통과하면 확정하고, 부족하면 다른 위치로 이동해 다시 보고, 기한 안에 확인하지 못하면 미확인 상태로 사람에게 넘깁니다. 여기에 사람 검출기를 추가 조건으로 붙일 수 있고, 이 게이트의 유무가 뒤에 나올 비교 실험의 변수입니다."

주의: 현재 근거 확인은 사람 검출과 제한 문구 규칙으로 근사한 것이다. 충분성을 측정하는 모델이 아니다. YOLO 통과가 대상의 정체나 자세의 정확성을 보장하지 않는다.

## 5. 동작 예시: 확인할 수 없으면 다시 본다 — 55초

### 핵심 메시지

근거가 부족할 때 재관측하고, 새 근거로 답하는 절차가 실제로 이어진다. 화면 오른쪽에서 TRACE가 관측마다 내린 판단이 보인다.

### 화면 본문

영상만. 슬라이드에 별도 글머리표를 두지 않는다. 영상 안의 모니터 화면이 설명을 맡는다.

화면 왼쪽은 카메라 영상(실험실 전경, 고정 카메라, 로봇 카메라), 오른쪽은 점검 요청과 TRACE의 단계별 기록이다.

1. 점검 요청: "작업자가 있는지, 어떤 자세인지 확인하라"
2. ① 고정 카메라 관측 — VLM 응답이 형식 오류 → 무효 처리
3. ② 로봇 카메라 관측(입구) — 사람 불확실 · 자세 미확인 → **근거 불충분, 답을 확정하지 않는다**
4. ③ 재관측 결정 — 서쪽 관측 위치로 이동
5. ④ 로봇 카메라 관측(서쪽) — 사람 보임 · 서 있음 → **근거 채택**
6. 답변: 작업자 있음 · 서 있음 (이동 전후 화면 비교)

영상 34.5초 + 설명 20초. 영상 중에는 ②의 "근거 불충분"과 ④의 "근거 채택" 두 지점만 짚는다.

주의:
- 이 영상은 2장 실패 실행을 고친 결과가 아니다. 같은 조건(west4_standing)을 2026-11-10에 따로 실행한 시연이다. "같은 조건의 별도 실행"이라고 말한다.

- ②에서 사람 검출 게이트도 "검출 안 됨"이었다. VLM 스스로도 추가 관측이 필요하다고 답한 경우라서, 게이트만의 효과로 설명하지 않는다.

## 6. 평가 설계: 정답과 근거를 따로 센다 — 80초

### 핵심 메시지

정답 일치만 세지 않는다. 인용한 영상이 답을 뒷받침하는지를 별도로 채점한다.

### 화면 본문

**한 실험실 · 20조건 × 게이트 OFF/ON = 40회**
서 있음 10 / 누워 있음 10 · 관측 가능 16 / 관측 불가 4

| 지표 | 판정 기준 |
|---|---|
| **근거 있는 정답** | 실제 자세와 일치 + 인용 영상에 작업자가 있음 + 사람이 그 영상에서 자세를 판독할 수 있음 |
| **대상 없는 확정** | 자세를 확정했는데 인용 영상에 작업자 픽셀이 0 |
| 적절한 인계 | 관측 불가 조건에서 기한 내 미확인으로 인계 |
| 비용 | 실행 시간 · 이동 거리 · 모델 호출 수 |

OFF와 ON은 모델·카메라·이동 도구·예산이 같고, **검출 게이트만 다르다.**

### 자료

- `s01_cover/lab_overview.jpg` — 실험 환경 설명용으로 재사용 가능.
- 표는 PPT에서 직접 만든다. 위 두 행을 굵게.

관측 위치 배치도와 평가 경로 도식은 아직 없다. 넣으려면 새로 그려야 한다. 없어도 이 장은 표만으로 성립한다.

### 발표 메모

"2장의 사례를 잡아내려면 채점 방식이 달라야 합니다. 시뮬레이터가 알려 주는 작업자 영역으로 인용 영상에 작업자가 있는지 확인하고, 그 영상에서 자세를 읽을 수 있는지는 사람이 모델 답을 가린 채 판독했습니다. 이 정보는 채점에만 쓰고 로봇에게는 주지 않았습니다. 성공한 실행만 고르지 않고 20회 전부를 분모로 둡니다."

발표자 참고: 20조건은 한 실험실의 배치 변형이며 독립된 환경 20개가 아니다. 사람 판독자는 1명이다. 게이트 임계값 0.60은 이전 개발 영상에서 정했고 비교 실험 중에는 바꾸지 않았다.

## 7. 초기 실험: 근거 확인은 많이 거부하는 것과 다르다 — 80초

### 핵심 메시지

초기 구현은 판독 가능한 관측까지 버리고 있었다. 평가를 분리했기 때문에 이 문제가 보였다.

### 화면 본문

**초기 40회: 근거 있는 정답이 OFF 4/20, ON 6/20에 그쳤다.**

실패한 실행 22회의 대표 프레임을 사람이 판독해 보니:

- 21장은 사람이 자세를 읽을 수 있었다.
- 14장은 Qwen의 자세 판독도 맞았다. **그런데 "뒷모습", "얼굴 안 보임" 같은 제한 문구가 하나라도 있으면 근거에서 탈락시키고 있었다.**
